# The Mike Ross Layer: Documents, Books, Text

Mike Ross (*Suits*) reads a law book once and quotes page 312 years later. That's fiction.
There's no solid evidence that adults have truly "photographic" (eidetic) memory. Eidetic
imagery has been reported in a small fraction of children and fades with age, and claims of
adult photographic memory haven't survived testing. Speed-reading claims don't survive
either: reviews of the reading research (e.g. Rayner et al., 2016) find that going much faster
than normal reading trades away comprehension.

What *is* achievable, and looks like Mike Ross from the outside, is a disciplined way to
**encode documents** so that structure, key facts, numbers, and chosen exact quotes come back
on demand.

## 1. Read for structure first (the skeleton palace)

1. **Survey** (2–5 min): table of contents, headings, abstract, conclusion, figures. Count the
   sections.
2. **Build the skeleton**: one palace (or one room) per document, one locus per section, in
   order. Put a *title image* for each section at its locus before reading the body.
   Now you know where everything goes, and you'll know "where in the document" something is.
3. **Read** section by section with a question in mind ("what does this section claim?").

## 2. Encode the content

Per section, at its locus, place 1–3 linked images for:
- **The main claim or rule**: an action scene.
- **Key numbers**: number-code images (brown-system.md §4) (deadlines, thresholds, amounts, percentages).
- **Names and parties**: substitute-word people (a case name, an author, a company).
- **Exceptions and conditions**: put them *on* the main image as a modifier (a red "STOP" sign
  stuck to it for "unless…").

**Legal and technical citations**: case name → image; holding → what the image does; year
and citation numbers → number-code images in the same scene. *Section 230* = 23 + 0 → a giant
**name** tag (23) at the **zoo** (0), shielding a website from lawsuits.

**Code and specs**: module = room; key functions = objects; config numbers and port numbers =
number-code images. For understanding a codebase, pair this with the `learn-anything` skill.

## 3. Verbatim memorisation (quotes, definitions, poems, scripts)

Only for text that must be exact.
1. **Understand it first**: paraphrase it. Meaning is the scaffold for the words.
2. **Chunk** by clause or line.
3. **First-letter cue**: write the first letter of each word ("Four score and seven years
   ago" → "F s a s y a"). Recite from the letters; this forces recall instead of re-reading.
4. **Cumulative rehearsal**: line 1; then lines 1–2; then 1–3 and so on. Always recite from the
   start.
5. **Fade the cues**: full text → first letters → first letter of each line → nothing.
6. **Anchor lines to loci** for long texts (one line or stanza per locus) so you can enter
   anywhere.
7. **Spaced recall** (brown-system.md §9). Recite aloud from memory, then check.

## 4. "Page 312"

To remember *where* something is (a page, a section number, a clause), add a location image:
the page or section number as a number-code image in the scene. "Clause 14.2" = lorry (14) + hen (2)
at that clause's locus. When someone says "it's in there somewhere", you can say where.

## 5. Reading volume

What the Mike Ross fantasy really represents is *breadth*: having read everything relevant.
That part is time and habit, not memory. Practical approach:
- Skim widely for gist. Fully encode only what matters (step 1 tells you what that is).
- Encode a one-line summary of each important document into a "library" palace: one locus
  per book or document, with its core image.
- Review the library palace monthly; the summaries keep the details reachable.

## Honest limits

- Encoding a document this way takes **3–10× longer** than reading it. Choose what deserves it.
- Retrieval stays strong only with review.
- Understanding still matters most. A perfectly memorised clause you can't apply is trivia.
